# 文章摘要优化与批量生成设计

日期：2026-08-10

## 背景

文章摘要功能上线后存在三个问题：

1. 默认摘要提示词要求以「本文讲述了」开头，首页列表看起来生硬，不像正常句子。
2. 文章编辑页有手写摘要输入框，与「摘要由 AI 自动生成」的定位重复。
3. 摘要只能逐篇在文章管理页点按钮生成，老文章补摘要成本高。

## 目标

- 新摘要为一段自然的中文叙述句，不带任何开场套话，不超过 120 字。
- 编辑页移除摘要输入框，摘要完全由 AI 生成。
- 后台一键批量生成全部文章摘要，并发 5，可选手动替换全部或只补无摘要的。

## 设计

### 1. 摘要提示词优化与 DB 迁移

新默认提示词 `DefaultAbstractPrompt`（`blog-backend/internal/modules/system/defaults.go`）：

```
你是博客文章的摘要编辑器。请基于原文生成一段准确、紧凑、可直接展示给读者阅读的中文摘要。

摘要要求：
1. 提炼文章讨论的核心问题、主要方法或观点，以及最重要的结论或读者价值。
2. 只使用原文明确提供的信息，不补充外部知识，不虚构数据、结论或作者立场。
3. 删除代码细节、链接、目录、寒暄、重复表述和无关示例。
4. 直接输出正常的叙述句，不得使用任何开场套话（不要出现「本文讲述了」「这篇文章」「在这篇文章中」等表述），不得超过 120 字。

输出要求：
只输出摘要正文，并用一对半角方括号完整包裹，方括号外不得有任何文字。
格式示例：[一句完整的自然语言摘要，不超过 120 字]

<article>
{{.ArticleContent}}
</article>
```

迁移：把当前 `DefaultAbstractPrompt` 原文挪进新的 legacy 常量，并在 `legacyPromptDefault` 注册。`ensureDefaults`（repository.go）会在存储值等于旧默认值时自动升级为新提示词，老库无需手动改。

代码兜底：`ProcessSummaryGeneration` 与批量任务保存摘要前，超过 120 个字符（rune）时截断。

### 2. 编辑页改动

- `blog-front/src/views/backend/PublishView.vue`：删除摘要输入框（el-divider + el-textarea）、`article.summary` 初始值与 `clear()` 中的重置。
- 后端 `SaveArticle` 的自动生成逻辑与 `UpdateArticle` 的摘要保留逻辑不变（编辑器不再传 summary）。

### 3. 批量生成

采用方案 A：后台任务 + 内部并发 5 + 静默轮询完成。

#### 后端

- 新任务类型 `AI_Gen_Batch_Summary`，注册于 task 包（复用 `SubmitTask` 机制，`TaskManager.RegisterBatchSummaryGenerationHandler` / `SubmitBatchSummaryGeneration`）。
- 任务负载 `AiGenBatchSummaryTask{ Mode string }`，mode 取值 `overwrite`（替换全部）与 `fill`（只补无摘要）。
- 批处理 handler（article 模块内，如 `batch_summary.go`）：
  - 按 mode 查询目标文章 ID 列表：`overwrite` 为全部文章；`fill` 为 `summary = '' OR summary IS NULL`（覆盖从未生成与曾经生成失败留空的）。两类均包含加密文章。
  - 用 `errgroup.SetLimit(5)` 并发执行；单篇失败仅计数，不中断批次。
  - 批次状态存于模块级内存结构（互斥锁保护）：`{ Running bool, Done, Failed, Total int }`，完成后保留状态供查询。
  - 提交时若已有批次在跑，直接返回「已有批次在生成」错误。
- 新接口（article/module.go 路由）：
  - `POST /admin/article/summaries/batch` body `{"mode":"overwrite"|"fill"}` → 立即返回；前端随后轮询状态。
  - `GET /admin/article/summaries/batch` → `{ running, done, failed, total }`。
- 单篇生成的 `SubmitSummaryGeneration` 逻辑不变。

#### 前端

- `ManagerView.vue`「文章管理」tab 顶部加「一键生成摘要」按钮 → `ElMessageBox` 弹窗单选模式（替换全部 / 只补无摘要）→ 调批量接口。
- 按钮进入「生成中」禁用态，每 3s 静默轮询状态接口；完成时 `notify` 提示「成功 X 篇 / 失败 Y 篇」并触发列表刷新；批次进行中再次点击提示已有批次在跑。
- 不展示进度条，只有开始与完成两个提示。

### 4. 摘要缓存 key 修复

`platform/ai/service.go` 的 `generateSummaryCacheKey` 目前取正文前 50 字符，批量生成时多篇开头相同的文章会互相串摘要。改为对全文做 SHA-256（或 fnv64）取摘要作 key，前缀 `ai:summary:` 不变。

## 错误处理

- 单篇生成失败：记录失败计数与日志，继续批次；最终以失败数通知。
- 批次中服务重启：内存状态丢失，前端轮询得到 404 时视为完成并提示「状态未知，建议重试」。
- AI 未配置：批处理直接返回错误，前端提示。

## 测试

- system：默认提示词迁移测试（旧默认值升级为新默认值，非默认值不覆盖）。
- article：批处理 handler 测试 —— fill/overwrite 目标选取、并发上限生效（fake AI 服务记录并发峰值 ≤5）、失败计数、重复提交被拒。
- ai：缓存 key 对相同前 50 字符但不同全文的文章不串摘要。

## 影响面

- 配置：`DefaultAbstractPrompt` 变更；老库通过迁移自动升级。
- 数据库：无表结构变更。
- 前端：PublishView 移除输入框；ManagerView 增加批量按钮与轮询。
